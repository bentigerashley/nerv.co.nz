Ideation: NERV command-site rebuild

A visual direction for a self-contained portfolio experience that keeps the useful links visible while drawing its command language from the supplied NGE screens.

Grounding context

The existing site is a Next.js portfolio whose Directory contains four project links and whose External Signals point to GitHub, Discord, and LinkedIn. Its current visual vocabulary already establishes an off-white display face with horizontal compression, a mono data face, alert red/orange, and terminal mint. The supplied NGE reference set repeats red bar charts, mint traces, radial plots, diagonal safety stripes, status labels, and hexagonal warning fields. The project has no existing standalone microsite under inspo/.

Topic axes

Entry and motion · Information hierarchy · Signal visualisation · Link discovery · Responsive and accessible operation

01. Hexagonal warning gate

Description
Open on a short, staged warning sequence: alert hexagons, status copy, boot progress, and a bypass control. It establishes the world before yielding immediately to the portfolio.
Axis
Entry and motion
Basis
direct: `nge9.jpg` is a red warning field built from repeated hexagons; `nge4.jpg` uses high-priority status typography and alarm color.
Rationale
The requested opening becomes a meaningful threshold instead of a decorative loading delay.
Downsides
Animation can delay access, so it needs a bypass and reduced-motion route.

Complexity

02. Command dashboard, not a poster

Description
Use a clear hero panel with operational status, meter bars, a waveform, a circular target graphic, and concise navigation. Each data shape receives a content label and supports the hierarchy rather than filling every gap.
Axis
Information hierarchy
Basis
direct: `nge1.jpg`, `nge2.jpg`, and `nge10.jpg` combine several chart types in bounded sections. reasoned: grouped panels preserve scan paths better than an unstructured collage.
Rationale
It captures NGE density while letting a visitor find the portfolio’s purpose in one glance.
Downsides
Too many widgets would become visual noise; the dashboard needs strict hierarchy.
Confidence
92%
Complexity
Medium

03. Directory as project records

Description
Turn each retained project into a numbered record with stack/status metadata, a description, and an unambiguous launch link.
Axis
Link discovery
Basis
direct: the existing Directory already carries four clear project names and descriptions. reasoned: the record metaphor aligns with the system interface without hiding the primary action.
Rationale
It retains the site’s highest-value content and makes it more scannable.
Downsides
Invented technical metadata could misrepresent projects; only known labels should be used.
Confidence
96%
Complexity
Low

04. External signals as outbound ports

Description
Keep the three social destinations as high-contrast port cards with platform name, signal code, and external-link affordance.
Axis
Link discovery
Basis
direct: the existing External Signals component contains GitHub, Discord, and LinkedIn. reasoned: named actions work better than icon-only controls for first-time visitors.
Rationale
It retains the requested page while giving the social links a stronger visual role.
Downsides
Platform marks need not be copied; text labels are sufficient.

05. Reference deck as a lower-priority archive

Description
Place selected supplied images in a controlled, captioned archive panel near the end of the page. The image deck enriches the visual language after the visitor can reach the useful links.
Axis
Signal visualisation
Basis
direct: the user supplied thirteen NGE images, including static and animated studies. reasoned: deferred rich media avoids crowding the first decision screen.
Rationale
It gives the inspiration material an explicit home without turning the portfolio into an image dump.
Downsides
Large imagery can affect initial load; render compact previews and lazy-load them.
Confidence
86%
Complexity
Low
